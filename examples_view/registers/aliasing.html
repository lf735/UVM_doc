Aliased Registers

Models hardware registers that can be accessed via multiple distinct memory addresses, maintaining synchronized mirrored values across aliases.

Key UVM APIs: uvm_reg uvm_reg_field uvm_reg_cbs predict

Source Specification & Design Notes

Test Intent & Implementation Walkthrough
Source: regmodel.sv

This example demonstrates how to model aliased registers i.e. registers that are present at two physical addresses, possibily with different access policies.

In this case, we have a register "R" which is known under two names "Ra" and "Rb". When accessed as "Ra", field F2 is RO.

Testbench Architecture Topology

addr 0x00 reg_primary
addr 0x04 reg_alias
Same underlying HW bits

26class dut;
27 static bit [7:0] F1 = 0;
28 static bit [7:0] F2 = 0;
29 
30 static task rw(reg_rw rw);
31 case (rw.addr)
32 'h000: // Ra
33 if (rw.read) rw.data = {8'h00, F2, 8'h00, F1};
34 else if (rw.byte_en[0]) F1 = rw.data[7:0];
35 'h100: // Rb
36 if (rw.read) rw.data = {8'h00, F2, 8'h00, F1};
37 else begin
38 if (rw.byte_en[0]) F1 = rw.data[7:0];
39 if (rw.byte_en[2]) F2 = rw.data[23:16];
40 end
41 endcase
42 // $write("%s\n", rw.convert2string());
43 endtask
