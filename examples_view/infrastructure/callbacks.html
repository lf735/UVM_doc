Callback Hooks

Implements non-intrusive testbench modifications using uvm_callback and uvm_register_cb to alter component behavior or inject errors without editing component source code.

Key UVM APIs: uvm_callback `uvm_register_cb `uvm_do_callbacks

Source Specification & Design Notes

Test Intent & Implementation Walkthrough
Source: top.sv

Typical Callback Application

This example demonstrates callback usage. The component developer defines a driver and driver-specific callback class. The callback class defines the hooks available for users to override. The component using the callbacks (i.e. calling the callback methods) also defines corresponding virtual methods for each callback hook. The developer implements each virtual methods to call the corresponding callback method in all registered callback objects using default algorithm. The end-user may then define either a callback or driver subtype to extend driver behavior.

Component Developer Use Model

Component developers defines transaction, driver, and callback classes.

54// CLASS: bus_tr
55//
56// A basic bus transaction.

59class bus_tr extends uvm_transaction;
60 rand int addr;
61 rand int data;
62 virtual function string convert2string();
63 convert2string = $sformatf("addr=%0h data=%0h",addr,data);
64 endfunction
65endclass

67 
68//------------------------------------------------------------------------------
69//
70// CLASS: bus_driver_cb
71//
72//------------------------------------------------------------------------------
73// The callback class defines an interface consisting of one or more function
74// or task prototypes. The signatures of each method have no restrictions.
75// The component developer knows best the intended semantic of multiple
76// registered callbacks. Thus the algorithm for traversal the callback queue
77// should reside in the callback class itself. We could provide convenience
78// macros that implement the most common traversal methods, such as sequential
79// in-order execution.
80//------------------------------------------------------------------------------
81 
82virtual class bus_driver_cb extends uvm_callback;
83 
84 virtual function bit trans_received(bus_driver driver, bus_tr tr);
85 return 0;
86 endfunction
87 
88 virtual task trans_executed(bus_driver driver, bus_tr tr);
89 endtask
90 
91 function new(string name="bus_driver_cb_inst");
92 super.new(name);
93 endfunction
94 
95 static string type_name = "bus_driver_cb";
96 
97 virtual function string get_type_name();
98 return type_name;
99 endfunction
100 
101endclass
102 
103 
104//------------------------------------------------------------------------------
105//
106// CLASS: bus_driver
107//
108//------------------------------------------------------------------------------
109// With the following implementation of bus_driver, users can implement
110// the callback "hooks" by either...
111//
112// - extending bus_driver and overriding one or more of the virtual
113// methods, trans_received or trans_executed. Then, configure the
114// factory to use the new type via a type or instance override.
115//
116// - extending bus_driver_cb and overriding one or more of the virtual
117// methods, trans_received or trans_executed. Then, register an
118// instance of the new callback type with an instance of bus_driver.
119// This requires access to the handle of the bus_driver.
120//------------------------------------------------------------------------------
121 
122class bus_driver extends uvm_component;
123 
124 uvm_blocking_put_imp #(bus_tr,bus_driver) in;
125 
126 `uvm_register_cb(bus_driver, bus_driver_cb)
127 
128 function new (string name, uvm_component parent=null);
129 super.new(name,parent);
130 in = new("in",this);
131 endfunction
132 
133 static string type_name = "bus_driver";
134 
135 virtual function string get_type_name();
136 return type_name;
137 endfunction
138 
139 virtual function bit trans_received(bus_tr tr);
140 `uvm_do_callbacks_exit_on(bus_driver,bus_driver_cb,trans_received(this,tr),1)
141 endfunction
142 
143 virtual task trans_executed(bus_tr tr);
144 `uvm_do_callbacks(bus_driver,bus_driver_cb,trans_executed(this,tr))
145 endtask
146 
147 virtual task put(bus_tr t);
148 uvm_report_info("bus_tr received",t.convert2string());
149 if (!trans_received(t)) begin
150 uvm_report_info("bus_tr dropped",
151 "user callback indicated DROPPED\n");
152 return;
153 end
154 #100;
155 trans_executed(t);
156 uvm_report_info("bus_tr executed",{t.convert2string(),"\n"});
157 endtask
158 
159endclass

165//
166// Group: End-User Use Model
167//
168//------------------------------------------------------------------------------
169// The end-user simply needs to extend the callback base class, overriding any or
170// all of the prototypes provided in the developer-supplied callback interface.
171// Then, register an instance of the callback class with any object designed to
172// use the base callback type.

174 
175import uvm_pkg::*;
176import bus_driver_pkg::*;
177 
178//------------------------------------------------------------------------------
179//
180// CLASS: my_bus_driver_cb
181//
182//------------------------------------------------------------------------------
183// This class defines a subtype of the driver developer's base callback class.
184// In this case, both available driver callback methods are defined. The
185// ~trans_received~ method randomly chooses whether to return 0 or 1. When 1,
186// the driver will "drop" the received transaction.
187//------------------------------------------------------------------------------
188 
189class my_bus_driver_cb extends bus_driver_cb;
190 
191 function new(string name="bus_driver_cb_inst");
192 super.new(name);
193 endfunction
194 
195 virtual function bit trans_received(bus_driver driver, bus_tr tr);
196 static bit drop = 0;
197 driver.uvm_report_info("trans_received_cb",
198 {" bus_driver=",driver.get_full_name()," tr=",tr.convert2string()});
199 drop = 1 - drop;
200 return drop;
201 endfunction
202 
203 virtual task trans_executed(bus_driver driver, bus_tr tr);
204 driver.uvm_report_info("trans_executed_cb",
205 {" bus_driver=",driver.get_full_name()," tr=",tr.convert2string()});
206 endtask
207 
208 virtual function string get_type_name();
209 return "my_bus_driver_cb";
210 endfunction
211 
212endclass
213 
214

216//
217// CLASS: my_bus_driver_cb2
218//
219//------------------------------------------------------------------------------
220// This class defines a subtype of the driver developer's base callback class.
221// In this case, only one of the two available methods are defined.

224class my_bus_driver_cb2 extends bus_driver_cb;

226 function new(string name="bus_driver_cb_inst");

229 
230 virtual task trans_executed(bus_driver driver, bus_tr tr);

242//------------------------------------------------------------------------------
243//
244// MODULE: top
245//
246//------------------------------------------------------------------------------
247// In this simple example, we don't build a complete environment, but this does
248// not detract from the example's purpose. In the top module, we instantiate
249// the bus_driver, and one instance each of our custom callback classes.
250// To register the callbacks with the driver, we get the global callback pool
251// that is typed to our specific driver-callback combination. We associate
252// (register) the callback objects with driver using the callback pool's
253// ~add_cb~ method. After calling ~display~ just to show that the
254// registration was successful, we push several transactions into the driver.
255// Our custom callbacks get called as the driver receives each transaction.
256//------------------------------------------------------------------------------
257 
258module top;
259 import uvm_pkg::*;
260 import bus_driver_pkg::*;
261 
262 bus_tr tr = new;
263 bus_driver driver = new("driver");
264 my_bus_driver_cb cb1 = new("cb1");
265 my_bus_driver_cb2 cb2 = new("cb2");
266 
267 initial begin
268 bus_driver_cbs_t::add(driver,cb1);
269 bus_driver_cbs_t::add(driver,cb2);
270 bus_driver_cbs_t::display();
271 for (int i=1; i<=5; i++) begin
272 tr.addr = i;
273 tr.data = 6-i;
274 driver.in.put(tr);
275 end
276 begin
277 uvm_report_server svr;
278 svr = uvm_report_server::get_server();
279 svr.summarize();
280 end
281 end
282 
283endmodule
